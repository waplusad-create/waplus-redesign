## 0. 한 장 요약

자사몰(`wapluscommerce.cafe24.com`)에 주문이 들어오면 **상품에 따라 처리 경로가 둘로 갈린다.**

| 경로 | 대상 | 처리 방식 | 송장 확보 |
|---|---|---|---|
| **A. 도매매 위탁 발주** | 자사몰 4종(프레피 니삭스·레그워머·수면양말·기모 발가락양말) | 도매매에 수취인 정보로 발주 → e-money 결제 | 도매꾹·도매매 공급사 입력분 회수 |
| **B. 사입 3PL 출고요청** | 자사몰 **2종(남자 벨트 1+1 · 여성 양말 10켤레 세트)** | 3PL(파주 물류센터)에 **이메일 출고 요청** | 3PL 회신(엑셀·메일)에서 회수 |

현재 이 두 경로 모두 **수작업**이다. 스피드고전송기 2.0은 스마트스토어 3개·쿠팡에만 연동돼 있고 **카페24(자사몰)는 연동돼 있지 않다.** 따라서 자사몰 주문은 지금 어떤 시스템으로도 자동 전달되지 않는다.

**결론(권장안)**
1. **도매매**는 새로 개발하지 말고 **카페24 앱스토어의 '도매매' 앱 + 카페24전송기**를 설치·연결한다(주문 수집 자동, 공급사 발주·결제는 버튼). 전면 무인화가 필요하면 **도매꾹 Private API(자사몰 직접 연동형) 승인** 후 `setOrder`/`setOrdOkDeli`로 직접 연동한다.
2. **3PL**은 표준 출고요청 메일 포맷(§6)을 정해 **자동 발송 + 회신 파싱 + 카페24 송장 등록**을 붙인다. 더 좋은 대안은 3PL에 **카페24 주문 연동**을 요청하는 것(해당 업체가 쇼핑몰 주문 연동 서비스를 운영 중) — §9-3.
3. **먼저 3PL 업체 특정**(§9-1): '플로우박스'라는 이름의 파주 업체가 2곳 확인돼 수신 주소를 잘못잡을 위험이 있다.

## 3. 전체 흐름

```
[카페24 자사몰] 주문 결제완료(PAID)
        │  (5분 폴링: 카페24 Admin API 주문조회)
        ▼
[주문 라우터] product_no 기준 분류 (§2)
        ├── A그룹(위탁) ──► [도매매 발주 어댑터]
        │                    ├ 경로A1: 카페24 도매매앱 주문관리 → '주문 및 결제' 버튼(e-money)
        │                    └ 경로A2: 도매꾹 Private API setOrder (완전 자동)
        │                    → 도매매 주문번호 회수 → 송장 대기
        └── B그룹(사입) ──► [3PL 출고요청 어댑터]
                             → 출고요청 메일 자동 발송(+CSV 첨부)
                             → 회신(엑셀·메일) 파싱 → 송장 회수
        ▼
[송장 등록] 카페24 주문 배송정보 등록(택배사+송장번호) → 주문상태 '배송중'
        ▼
[알림] 신규주문 / 발주실패 / 잔액부족 / 3PL재고부족 / 회신지연
```

한 주문에 A·B 상품이 섞이면 **부분 출고(송장 2개)** 로 처리한다. 카페24는 주문 1건에 송장 여러 개를 넣을 수 있으므로, 상품별로 나눠 발송 처리한다.

## 4. 경로 A — 도매매 위탁 자동발주

### 4.1 두 가지 구현안

| 안 | 방식 | 자동화 수준 | 준비 기간 | 비고 |
|---|---|---|---|---|
| **A1 (즉시)** | 카페24 앱스토어 '도매매' 설치 → 카페24전송기 → 주문관리에서 도매매 API KEY 입력 | 주문 **수집 자동(약 5분)**, 공급사 주문·e-money 결제는 **버튼 클릭**, 송장은 '배송상태갱신' 버튼으로 카페24에 반영 | **1일** | 개발 0. 옵션 변경 확인 팝업이 뜨므로 발주 전 옵션 검수 필요 |
| **A2 (완전 자동)** | 도매꾹 OpenAPI **Private API** 권한 승인(자사몰 직접 연동형) → `setOrder`(주문서 생성) + `setOrdOkDeli`(송장 등록) | 전 구간 자동 | 권한 심사 영업일 1~3일 + 개발 3~5일 | e-money 자동 차감. 상한·승인 규칙(§4.4) 필수 |

**권장**: A1로 오늘 바로 주문이 새지 않게 막고, A2는 병행 개발. A1만으로도 "주문이 들어오면 도매매 주문관리에 자동으로 쌓인다"까지는 무인이다.

### 4.2 도매꾹 API 사실관계 (구현 전제)

- Endpoint: `https://www.domeggook.com/ssl/api/` (POST, form-urlencoded)
- 공통 파라미터: `ver`, `mode`, `aid`(API KEY), `id`(회원 ID), `sId`(로그인 API로 발급받은 세션), `om=json|xml`
- **주문서 생성** `mode=setOrder` ver 4.3 — `receipt`(현금영수증 0/1), `item[상품번호]:dome||P||옵션|수량||판매자전달사항||배송요청사항`, `deliinfo:이름|이메일|우편번호|주소|상세주소|휴대폰|전화|받는분회사`
- **발송정보 입력** `mode=setOrdOkDeli` ver 1.0 — `no`(주문번호), `type`(add/edit), `deliMethod`(TB 택배), `deliCompany`(HANJIN·HYUNDAI·KGBL·EPOST 등), `deliCode`(송장번호)
- **권한**: 2026-03-26부터 Private API 승인제. `로그인/주문수집/발주처리`는 **사전 권한 신청·승인 필수**(API 발급/관리 → Private API → 권한신청, 영업일 1~3일). 신청 유형 = **자사몰 직접 연동형**.
- 주문 수집 API는 `for=buy`(구매=발주) / 판매 구분이 있으므로 **구매(발주) 방향**으로 사용.
- 문의: `techsupport@ggook.com`

### 4.4 자금·승인 규칙 (반드시 지킬 것)

- 결제는 **e-money 선충전 잔액**에서만 나간다. 잔액 < 주문금액이면 **발주 중단 + 즉시 알림**(충전은 대표님 결재 사항).
- 자동발주 상한(제안, **대표님 승인 필요**): 1건 **50,000원 이하**, 1일 **10건 이하**, 1일 합계 **200,000원 이하**. 초과 건은 "승인 대기" 큐에 넣고 알림만 한다.
- 발주 취소·반품은 자동화하지 않는다. 출고 전 취소 요청이 오면 발주 취소 가능 여부를 사람이 판단(도매매 규정상 공급사 발주 후 취소는 공급사 협의).

## 6. 경로 B — 3PL 출고요청

### 6.1 트리거
- B그룹 상품이 포함된 주문이 **결제완료(PAID)** 상태가 된 시점.
- 묶음 발송: 같은 수취인/같은 날 주문은 1통으로 묶는다(포장 단위 최적화). 단 **주문번호는 행 단위로 유지**해 송장 매칭이 가능해야 한다.

### 6.2 발송 규칙
- 발신: 운영 메일 `<운영 메일 주소>` (SMTP/앱 비밀번호는 시크릿 보관)
- 수신: `<3PL 출고요청 수신 메일 — 내부 관리>`
- 제목: `[손맨삭스] 출고요청 2026-11-25 (3건)`
- 본문: 요약 표 + 건수 + 특이사항, **첨부: CSV(UTF-8 BOM)** — 엑셀에서 바로 열리도록 BOM 포함
- 발송 시각: 평일 09:00~16:00 사이 즉시. **출고 마감시간 확인 필요(§9-2)** — 마감 이후 주문은 다음 영업일 오전 통에 합류.

### 6.3 메일 본문 템플릿

```
제목: [손맨삭스] 출고요청 2026-11-25 (3건)

안녕하세요, 손맨삭스입니다.
자사몰(wapluscommerce.cafe24.com) 주문 출고를 아래와 같이 요청드립니다.

- 요청 건수: 3건 / 4개
- 상품: 남자 벨트 1+1 세트(2), 여성 양말 10켤레 세트(2)
- 첨부: sonmansocks_출고요청_20261125.csv

특이사항
- 2번 주문: 배송메시지 "부재 시 경비실" — 문 앞 부착 요청
- 3번 주문: 여성 양말 10SET+긴양말 3켤레 추가 구성(옵션 B)

출고 후 택배사·송장번호를 회신해 주시면 자사몰에 바로 반영하겠습니다.
감사합니다.
손맨삭스 드림 (<고객센터>)
```

### 6.4 CSV 컬럼 정의 (고정)

| # | 컬럼 | 예시 | 필수 |
|---|---|---|---|
| 1 | 주문번호 | 20261125000123 | Y |
| 2 | 주문일시 | 2026-11-25 09:12 | Y |
| 3 | 상품코드(SKU) | SON-13-B | Y |
| 4 | 상품명 | 여성 양말 10켤레 세트 | Y |
| 5 | 옵션 | 10SET+긴양말 3켤레 | Y |
| 6 | 수량 | 1 | Y |
| 7 | 수취인 | 홍길동 | Y |
| 8 | 연락처1 | 010-0000-0000 | Y |
| 9 | 연락처2 | | N |
| 10 | 우편번호 | 00000 | Y |
| 11 | 주소 | 서울특별시 ○○구 ○○로 1 | Y |
| 12 | 상세주소 | ○○타워 3층 | N |
| 13 | 배송메시지 | 부재 시 경비실 | N |
| 14 | 요청사항 | | N |

- 3PL이 자체 양식을 요구하면 **그 양식에 맞춰 출력하는 어댑터**를 둔다(내부 표준은 위 컬럼).
- 파일명: `sonmansocks_출고요청_{YYYYMMDD}_{n}건.csv`

### 6.5 회신 처리 (송장 회수)
1. 3PL 회신 메일(엑셀 첨부 또는 본문 표)을 **IMAP으로 폴링**(5분 간격, 제목/발신자로 식별).
2. 첨부 엑셀·CSV 파싱 → `주문번호` 또는 `SKU+수취인`으로 매칭.
3. 카페24 배송정보 등록(택배사 코드 + 송장번호) → 주문상태 '배송중'.
4. 파싱 실패·부분 회신은 **보류 큐**로 보내고 알림. **추정으로 송장을 넣지 않는다.**
5. 회신이 영업일 기준 **24시간** 넘으면 리마인드 메일 1회 + 알림.

### 6.6 재고 관리
- 3PL 보유 재고는 자사몰 재고와 자동 동기화되지 않는다(현재).
- 제안: 평일 09:00에 **재고 현황 요청 메일 1통**(SKU별 가용 수량) → 회신 파싱 → 자사몰 재고 반영, **안전재고(예: SKU당 10개) 이하 시 알림**.
- 장기 대안: 3PL의 주문 연동 서비스로 **카페24 연동 가능 여부 문의** — 가능하면 3PL 쪽에서 직접 출고·송장 처리되어 메일 파싱 자체가 불필요해진다(§9-3).

## 7. 송장 등록 (A·B 공통)

- 카페24 Admin API의 **주문 배송정보 등록** 기능 사용(엔드포인트·택배사 코드는 카페24 개발자센터 최신 문서 기준으로 확인 후 고정).
- 필요 값: 주문번호(order_id), 택배사 코드, 송장번호, 발송일.
- **자사몰 택배사 확정 필요(§9-5)** — 쿠팡은 한진택배, 도매매 공급사는 롯데택배를 쓰는 것으로 관측됨. 3PL 출고 택배사는 확인 필요.
- 송장 등록 후 카페24가 고객에게 배송 시작 알림을 발송한다(설정에 따름).

## 8. 운영·예외 처리

| 상황 | 처리 |
|---|---|
| 결제완료 전(입금대기/무통장 미입금) | 처리하지 않음. 입금 확인 후 시작 |
| 상품 매핑 없음(신규 상품) | 발주 금지, "매핑 필요" 알림. **신규 상품은 자동 발주하지 않는 것이 기본값** |
| 도매매 품절/판매중지 | 발주 중단, 알림 → 자사몰 품절 처리 여부 결정 |
| e-money 부족 | 발주 중단, 충전 요청 알림 |
| 3PL 재고 부족 | 메일 발송 전 재고 확인값이 부족하면 보류 + 알림 |
| 주소 오류(우편번호 불일치) | 배송 불가 → 보류 + 고객 확인 알림 |
| 주문 취소(출고 전) | A: 도매매 발주 취소 가능 여부 확인 후 처리 / B: 3PL에 출고 보류 메일 |
| 중복 수신(폴링 겹침) | 멱등성 키로 차단 |
| 자정 이후·주말 주문 | 다음 영업일 09:00 처리. 단 도매매 발주는 24시간 가능하므로 A그룹은 즉시 처리 가능 |

**실행 스케줄(제안)**: 평일 09:00~18:00 5분 폴링, 18:00~다음 09:00은 A그룹만 즉시, B그룹은 09:00 합류. 모든 실행은 로그를 남기고 하루 1회 요약 보고(주문 수·발주 성공/실패·송장 등록 건·보류 건).

## 9. 미확정 사항 (확인 필요)

1. **3PL 출고요청 수신 주소·담당자·양식** — **어느 '플로우박스'인지부터 확정해야 한다**(§1의 후보 ①·②). 확정 근거는 쿠팡 반품지에 등록된 '플로우박스 파주센터'의 상세 주소 또는 계약서·정산서. 업체 확정 후 실제 담당자·요청 양식(엑셀 템플릿) 확인 필요. 현재는 후보 ①(FLOW MAP) 공개 연락처를 잠정 지정.
2. **3PL 출고 마감시간 / 당일 출고 컷오프 / 회신 SLA**.
3. **3PL의 카페24 주문 연동 가능 여부** (메일 요청 방식보다 우선 검토).
4. **도매매 위탁 4종의 도매매 상품번호·옵션 코드** (§4.3 표 채우기).
5. **자사몰 택배사**와 카페24 송장 업로드 방식.
6. **자동발주 자금 상한**(§4.4 제안값 승인 여부).
7. **도매꾹 Private API 권한 신청**(자사몰 직접 연동형) — 사업자 정보 기반.
8. **카페24 Admin API 앱 생성·토큰 발급**(자사몰).
9. **프레피 니삭스(11) 공급처** — 위탁인지 사입인지.

## 11. 테스트 케이스

1. 단일 상품(12 벨트) 1건 → 메일 1통, CSV 1행, 송장 1건 등록
2. 옵션 추가금 있는 주문(13 옵션B 18,400원 / 14 블랙 21,530원) — 금액 일치
3. **혼합 주문**(13 + 14) → A·B 분리, 송장 2건, 부분 배송 상태 정상
4. 같은 수취인 2건 → 묶음 메일 1통, 주문번호 2행, 송장 각각 매칭
5. 무통장 미입금 주문 → 처리 안 됨
6. 도매매 품절 상품 주문 → 발주 차단 + 알림
7. e-money 부족 → 발주 차단 + 알림
8. 3PL 재고 0 → 메일 미발송 + 알림
9. 회신 지연 24h → 리마인드 1회
10. 동일 주문 2회 수신 → 중복 발주 없음
11. 출고 전 취소 → 보류 메일 + 발주 취소 확인

## 12. 보안 · 개인정보

- **비밀정보**: 카페24 API 토큰, 도매꾹 API KEY, 메일 계정 비밀번호, 쇼핑몰 계정 비밀번호 → **환경변수·시크릿 저장소**에만 보관. 코드·문서·레포에 절대 기재 금지.
- **수취인 개인정보**: 발주·출고 목적 범위 내 사용, 발송 완료 후 **90일** 보관 후 파기. 로그에는 이름·연락처 마스킹(예: 홍*동, 010-****-0000).
- **메일 발송 계정**: 운영 계정과 자동화 계정을 분리하면 사고 범위가 줄어든다(가능하면 자동화 전용 계정 발급).
- 이 문서는 공개 저장소용이므로 계정 ID·연락처·잔액 등 실값을 넣지 않는다.
